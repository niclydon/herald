# Herald: give your agent a light and a voice

Herald is a small physical companion for Muse and MCP agents. Two RGB LEDs
can show that an agent is working, finished, or needs attention; a speaker
can read its reply or announce a result. It runs on an HW678 ESP32-S3 N16R8
with an external I2S amplifier and two ordinary four-leg RGB LEDs.

It began as a bare development board and a speaker test. Speech came next,
then two independently controlled LEDs, a narrated light show, remote settings,
and an MCP bridge so other agents could use the same hardware. The result is
a community extension of the [Meta Muse Gadget SDK](https://github.com/facebookincubator/muse-gadget-sdk),
with its upstream history and attribution preserved.

## What you can do

Ask Muse to speak its replies through the desk speaker, or ask Codex or Claude
Code to fade the LEDs blue while working and announce completion in green.
Use the CLI in a script, set each LED's color directly, or run chase, alternate,
fade and sparkle patterns. The narrated showcase combines speech, both LEDs
and a synthesized melody, with a countdown for recording it.

Volume and brightness defaults persist across restarts. Remote commands expose
Wi-Fi status and scans, device information, diagnostics, cancellation and OTA
updates. Agents must actually invoke the tools: installing the MCP server does
not automatically add notifications to every task.

## Two ways to reach the same hardware

Muse uses the SDK's existing Link connection. Other agents and shell scripts
use the optional Herald HTTPS endpoint through the shared client, CLI or MCP
server. Both paths reach the same firmware command handlers. LAN clients have
an ownership lease to coordinate effects; Muse remains outside that lease and
can supersede them.

Start with the [hardware and firmware guide](esp32/devices/herald.md), then add
[MCP access](herald-mcp/README.md) if you want other agents to participate.
The tested board is **HW678 N16R8, not a Seeed XIAO**. Follow the wiring guide
and use one current-limiting resistor per LED color channel.

Speech is generated by a separate text-to-WAV service you provide; Herald
plays the returned audio. There is no microphone, wake word, display or
Bluetooth speaker output in this build. Muse pairing requires your own account
and SDK token. The optional LAN control path uses separate local credentials.

This is a source-only community prototype, not an official Meta hardware
product. Personalized firmware contains credentials and is not distributed.
LAN administrative commands require explicit opt-in. See the setup and audit
guides for the development-key trust model and verification limits.

Muse gadgets are open source devices you build yourself. Program an
off-the-shelf ESP32 board or set up a Raspberry Pi with our device SDKs, then
connect Muse to your displays, buttons, sensors, actuators, and whatever else
you've got lying on your workbench.

We open sourced the SDKs and firmware here. It's built by hackers, for hackers,
just for fun. Side effects of tinkering may include bricked boards, voided
warranties, brownouts, or bankruptcies. Proceed at your own risk!

| | |
|---|---|
| [**ESP32 Device SDK**](esp32) | Connect your ESP32 board to Muse through our open source SDK. Throw in a screen to show images, add audio in and out, or wire up other sensors. |
| [**Linux Device SDK**](linux) | Turn that spare Raspberry Pi or Linux box into a Muse gadget. Hack in your own commands to let Muse handle sysadmin chores or your Home Assistant setup. |
| [**Muse Gadgets Test**](android/musegadgetstest) ([iPhone](ios/musegadgetstest)) | Stream your phone's camera, or a clip, to an ESP32 gadget's screen over Wi-Fi: H.264 or VP8 decoded on the board, 30 fps on the round 466 px boards. [`protocols/VIDEO.md`](protocols/VIDEO.md) explains how. |

Before you flash or pair a gadget, get an
[SDK token](https://gadgets.muse.ai/settings/sdk-tokens) and review the
[Gadget SDK Terms](https://gadgets.muse.ai/sdk-terms). Every gadget needs a
token to pair.

ESP32 and Linux gadgets pair with the Muse app on iOS and Android, via
Settings > Devices. Turn on Developer mode there first, then look for devices
prefixed with "MuseGadget".
Each directory has a `README.md` to get started and an `AGENTS.md` for coding
agents like [Muse Code](https://developer.meta.com/ai/lp/muse-code/).

For battery-input power profiling, see the [porting recipe](esp32/docs/power/README.md).
The opt-in diagnostic core is board-neutral; boards supply its hooks and state
matrices, and [power_sweep.py](esp32/tools/power/power_sweep.py) drives the
USB-free sweep. The isolated diagnostic does not pair or need an SDK token;
fixture safety and explicit hardware authorization still come first, as the
[PPK2 rules](esp32/docs/power/ppk2.md) describe.
